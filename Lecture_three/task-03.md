# Практичні завдання

## Завдання 3. Тести для власного варіанта першої лабораторної

**Мета:** додати автоматичні перевірки до вже виконаного завдання 1.1 першої лабораторної та перевірити зрозумілу помилку при діленні на нуль.

**Вихідний матеріал:** ваше виконане завдання 1.1 та його формули; [демонстраційний код варіанта 1](https://github.com/mitikov/applied-math-compute/blob/main/Lecture_one/Sample_solutions/06_lab_task_1_1_variant_1.py) є прикладом структури.

**Використовуйте саме свій раніше виконаний варіант:** не замінюйте його формули та початкові дані демонстраційним варіантом 1.

### А. Перевірка обчислень свого варіанта

1. Скопіюйте свій розв'язок в окремий файл, наприклад `lab_1_1.py`.
2. Винесіть обчислення у функцію з явними аргументами, яка **повертає** результати, а не лише друкує їх. Для варіанта 1 це могли б бути аргументи `x, y, z, b` та пара результатів `a, m`; у вашому варіанті склад аргументів і результатів має відповідати його умові.
3. Введення даних та друк, якщо вони залишаються у файлі, розмістіть під умовою `if __name__ == "__main__":`, щоб імпорт у тестах не запускав взаємодію з користувачем.
4. Створіть файл `test_lab_1_1.py` та імпортуйте потрібні функції.
5. Напишіть перевірки щонайменше для **двох різних наборів допустимих даних**:
   - початкових даних свого варіанта;
   - додаткового набору, який відповідає області визначення ваших формул.
6. Для кожного набору перевірте **всі результати**, які вимагає завдання 1.1. Очікування розрахуйте незалежно: вручну, калькулятором або за перевіреним розрахунком свого розв'язку; не створюйте контрольну відповідь повторним викликом перевірюваної функції.
7. Для результатів із дробовими числами використайте `pytest.approx` або `math.isclose` з явно обраним допуском. Наприклад, для очікувань, збережених із достатньою точністю, можна взяти абсолютний допуск `1e-8` та відносний `1e-9`; якщо очікування округлене, узгодьте допуск із цим округленням.

Заповніть таблицю перевірок:

| Сценарій | Вхідні дані | Очікувані результати | Допуск | Фактичний результат |
| --- | --- | --- | --- | --- |
| Початкові дані свого варіанта | | | | |
| Додаткові допустимі дані | | | | |

### Б. Окремий сценарій ділення на нуль

Додайте функцію **`divide(numerator, denominator)`** і використайте її для операцій ділення у своїх обчисленнях.

Контракт функції:

| Вхід | Очікувана поведінка |
| --- | --- |
| Ненульовий знаменник | Повернути частку |
| Нульовий знаменник, зокрема `0.0` | Підняти `ZeroDivisionError` з повідомленням **`Ділення на нуль не підтримується`** |
| Чисельник і знаменник одночасно нульові | Та сама помилка з тим самим повідомленням |

1. Додайте перевірку звичайного ділення з ненульовим знаменником.
2. Додайте тест, який викликає `divide` з нульовим знаменником.
3. У цьому тесті перевірте **і тип винятку `ZeroDivisionError`, і його повідомлення**. Для цього можна використати `pytest.raises` та перевірку тексту отриманого винятку.
4. Переконайтеся, що програма видає погоджену помилку, а не повертає `None`, нуль чи рядок замість числа. Самого `print` із повідомленням недостатньо.
5. Якщо у вашому варіанті існують допустимі за іншими умовами входи, які обертають знаменник формули на нуль, додайте також тест основної функції на таких входах.

**Особливість демонстраційного варіанта 1:** для дійсного `y` знаменники `0.5 + sin(y)**2` та `3 + y**2 / 5` завжди додатні. Тому підбором дійсних вхідних даних викликати ділення на нуль у цих формулах неможливо: сценарій перевіряйте прямим викликом `divide`, яку справді використано в основних обчисленнях. Не змінюйте математичну формулу свого варіанта лише заради отримання нуля.

### Запуск і перевірка

Встановіть pytest, якщо його ще немає:

```bash
python -m pip install pytest
```

Запустіть власний файл тестів:

```bash
python -m pytest -v test_lab_1_1.py
```

Мінімум — **4 тестові випадки**: два набори даних основної функції, звичайне ділення та ділення на нуль. Їх можна оформити окремими функціями або параметризованими випадками. Тест очікуваної помилки також має завершитися як **PASSED**, коли потрібний виняток із правильним повідомленням отримано.

### Питання до результатів

- Чому друк числа не замінює автоматичної перевірки?
- Звідки взято очікування й чому обраний допуск підходить?
- Чому перевірка лише типу помилки не гарантує наявності зрозумілого повідомлення?

**Що здати:**

1. Файл `lab_1_1.py` зі своїм варіантом, функцією обчислень і функцією `divide`.
2. Файл `test_lab_1_1.py` із перевірками результатів та винятку.
3. Заповнену таблицю перевірок із номером свого варіанта.
4. Скріншот підсумку запуску, де видно назви перевірок та всі успішні результати, включно зі сценарієм ділення на нуль.

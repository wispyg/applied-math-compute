# Практичні завдання

## Завдання 2. cyber-dojo: пишемо тести для Fizz Buzz

**Час виконання:** 10 хвилин.

**Мета:** написати власні тести, побачити невдалий запуск і виконати короткий цикл «тест — реалізація — повторна перевірка».

**Сервіс:** [cyber-dojo](https://cyber-dojo.org/creator/home).

### Підготовка

1. Створіть індивідуальну практику: **Practise solo / solo**.
2. Оберіть вправу **Fizz Buzz** та середовище **Python із pytest**; номер версії в назві середовища може відрізнятися.
3. Відкрийте файл реалізації та файл тестів. Початковий приклад на кшталт `answer() == 42`, якщо він присутній, є шаблоном середовища й не перевіряє Fizz Buzz.
4. Після відкриття редактора увімкніть таймер на **10 хвилин**.

У цій роботі перевіряємо функцію `fizzbuzz(n)` для додатних цілих чисел. Вона повертає **рядок** за такими правилами:

| Умова | Результат |
| --- | --- |
| Число кратне і 3, і 5 | `"FizzBuzz"` |
| Число кратне лише 3 | `"Fizz"` |
| Число кратне лише 5 | `"Buzz"` |
| Решта додатних цілих чисел | Саме число як рядок, наприклад `"1"` |

Якщо опис kata пропонує надрукувати послідовність від 1 до 100, для цієї 10-хвилинної роботи достатньо функції для **одного числа** та її тестів.

### А. Перший тест

1. Напишіть тест для одного звичайного числа, наприклад `1`.
2. Запустіть тести та прочитайте причину невдачі.
3. Додайте реалізацію, яка виконує перевірену вимогу, і повторіть запуск.

Переконайтеся, що початкова невдача пов'язана з відсутньою або неправильною поведінкою функції; синтаксична помилка чи неправильний імпорт потребують виправлення перед продовженням.

### Б. Розширення набору

Додавайте сценарії **по одному**, після кожного змінюючи реалізацію та повторно запускаючи весь набір:

| Вхід | Очікуємо | Що перевіряємо |
| ---: | --- | --- |
| `1` | `"1"` | Звичайний випадок |
| `3` | `"Fizz"` | Кратність лише 3 |
| `5` | `"Buzz"` | Кратність лише 5 |
| `15` | `"FizzBuzz"` | Одночасна кратність 3 і 5 |

Орієнтир — **4 успішні сценарії**; якщо встигнете, додайте власні числа. Можна використати окремі тестові функції або параметризацію. Початковий шаблонний тест про `42` не зараховуйте до власних сценаріїв Fizz Buzz.

### Фіксація результату

Після 10 хвилин зробіть останній запуск і скріншот, на якому видно сервіс, підсумок тестування та кількість успішних тестових випадків `N`. Якщо частина тестів ще падає, залиште це видимим і вкажіть фактичний результат: `N passed, M failed`.

### Питання до результатів

- Чому сценарій для `15` перевіряє поведінку, яку не гарантують окремі тести для `3` та `5`?
- Чи достатньо лише тесту для `1`, щоб довіряти всій функції?

**Що здати:** завантажити скріншот із результатом **«N тестів пройдено»** та підписом `cyber-dojo — Fizz Buzz — 10 хвилин — N = …`; за наявності невдалих випадків додатково вказати їх кількість. Окремий текстовий звіт не потрібний.
